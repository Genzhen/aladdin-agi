## 第 1 站 · 项目骨架与工程红线

**学什么**：一个"要拿去面试"的项目怎么立项——PRD → 目录 → 红线，而不是先写代码。
**读什么**：`docs/PRD*.md`（需求从哪来）、根 `CLAUDE.md`（红线：单文件≤300行/每目录 index.md/金额全整数）、每个目录的 `index.md`（共 7 份）。
**跑什么**：`ls` 逐层看目录，把每个 index.md 读一遍。
**现象**：你会发现每个目录都能回答"这是什么、为什么这么拆"——这就是评分项。
**练习**：合上文档，自己在纸上画目录树，标出每层职责。
**理解题**：为什么金额在链上/库里/前端分别用 BigInt/TEXT/浮点？（答案在 CLAUDE.md 红线区）

## 第 2 站 · MyToken（ERC20 + faucet + airdrop）

**学什么**：OZ 的 ERC20 怎么扩展出业务功能；`onlyOwner` 和时间锁。
**读什么**：`contracts/MyToken.sol`（133 行，重点 faucet 的 24h 冷却 mapping、airdrop 的 calldata 批量+等长校验）。
**跑什么**：`npx hardhat test test/MyToken.test.js`（9 绿）。
**现象**：faucet 领过一次再领会 revert "cooldown"——冷却不是前端禁用按钮，是合约拒绝。
**练习**：把空投常量（上架10/发单5/完单20）改掉重跑测试，观察哪条用例红了。
**理解题**：为什么 airdrop 要校验 calldata 等长而不是靠前端？

## 第 3 站 · AgentRegistry（登记簿）

**学什么**：struct + mapping 的"链上数据库"范式；nextId 从 1；事件省体积的取舍。
**读什么**：`contracts/AgentRegistry.sol`、`test/AgentRegistry.test.js`（6 绿）。
**跑什么**：`npx hardhat test test/AgentRegistry.test.js`。
**现象**：`AgentRegistered` 事件里**没有 tags**——这是故意的（事件省 gas），第 7 站会看到 Relayer 因此回链上 struct 补数据。
**理解题**：事件和 storage 各适合放什么？（提示：事件=日志不可读，storage=贵但可读）

## 第 4 站 · TaskEscrow（状态机 + 资金托管）★全项目核心

**学什么**：enum 状态机、`msg.value == price+fee` 精确校验、CEI 模式、nonReentrant、call 转账、permissionless 兜底。
**读什么**：`contracts/TaskEscrow.sol`（262 行）逐行读，注释就是讲义。重点四段：
1. `postTask`：多退少拒，value 必须**恰好等于** price+0.1%（bps 整数 10/10000）
2. `accept`：跨合约校验 `registry.ownerOf(msg.sender)==msg.sender` + 6% 保证金
3. `executeRuling`：Split 怎么分、保证金怎么罚、仲裁费 0.5% 为什么**这时**才扣（openDispute 不收钱）
4. `claimTimeout`：为什么退款地址写死 `t.publisher`、任何人都能调却偷不走钱
**跑什么**：`npx hardhat test test/TaskEscrow.test.js`（15 绿）。
**练习**：故意把测试里的 `value` 多加 1 wei，看它怎么 revert——这就是 fail fast。
**理解题清单**：见 `docs/理解题_待答清单.md` 第 4~7 题。

## 第 6 站 · server：链是真相源，库是缓存

**学什么**：Express 分层（routes/ 瘦、逻辑在模块）、better-sqlite3 同步 API、**链=真相源**的架构观。
**读什么**：`server/index.js`（路由挂载总览）、`server/db.js`（建表+ALTER 迁移）、`server/routes/agents.js`。
**跑什么**：

```bash
cd server && node --test          # 匹配 8 用例（第 8 站细讲）
sqlite3 server/data/aladdin.db ".tables"
sqlite3 server/data/aladdin.db "SELECT id,name,score FROM agents;"
```

**现象**：库里 3 个 Agent、字段和链上一致——因为第 7 站的 Relayer 同步过 + 启动补账兜底。
**理解题**：为什么敢把 SQLite 放进 .gitignore？（提示：删掉 data/ 重启 server 会发生什么——亲手试！）
**练习（强烈推荐）**：`rm server/data/aladdin.db` → 重启 server → 看日志补账 → 库回来了。这就是"链为真相源"最爽的演示。

## 第 7 站 · Relayer：9 事件 + 双写对账 + 启动补账 ★面试高频

**学什么**：ethers v6 事件订阅、双写问题（链和库两个写入方）怎么用**对账钥匙**解决、宕机补账。
**读什么**：`server/relayer.js` 全文（注释即讲义）。三个名场面：
1. **AgentRegistered 补 tags**：事件没带 → `await registry.agents(id)` 回链上 struct 补
2. **TaskPosted 双写对账**：前端先 POST 草稿拿 priceWei → 钱包质押同一价格 → Relayer 按 (publisher+priceWei) 找到草稿合体。**价格就是天然对账钥匙**
3. **backfillAgents 启动补账**：服务器宕机期间的注册/结算，按链重建
**跑什么**：重启 server 观察启动日志里的补账输出；然后：

```bash
curl -s localhost:3001/api/tasks | head -40      # 任务库
curl -s localhost:3001/api/engine/overview        # 队列深度/模型状态/最近匹配
```

**练习**：发一个新任务（第 11 站前端或 `scripts/post-demo-task.js`），盯着 server 日志看 TaskPosted → 合体 → 入队三连。
**理解题**：双写对账为什么用 priceWei 而不用自增 id？为什么 `ev.log.blockNumber` 不是 `ev.blockNumber`（本项目真实踩过）？

## 第 8 站 · 三层匹配漏斗 ★★全项目面试核心

**学什么**：召回/精排/重排为什么分层；TF-IDF 和余弦相似度手写；逻辑回归+SGD 在线学习。
**读什么**（顺序读，`server/matching/index.md` 是地图）：
1. `v0.js`（55 行）：tag/category 交集召回 + Fisher-Yates 洗牌 + 冷启动全量兜底
2. `v1.js`（95 行）：tokenize → idf=ln((N+1)/(df+1))+1 → 稀疏 Map 向量 → 余弦
3. `v2.js`（90 行）：7 特征 [bias,tagOverlap,tfidfSim,scoreNorm,priceFit,categoryMatch,freshness] → sigmoid → SGD `w += lr*((y-p)*x - l2*w)`
4. `index.js`（150 行）：dispatch 编排 + recordClick 在线学习 + reasons() 可解释推荐
**跑什么**：

```bash
cd server && node --test test/matching.test.js    # 8 绿
curl -s -X POST localhost:3001/api/match/2/dispatch   # 对任务#2 重跑漏斗
curl -s -X POST localhost:3001/api/match/2/click -H 'content-type: application/json' -d '{"agentId":2}'
curl -s localhost:3001/api/engine/overview            # 看 model_weights 变化
```

**看什么现象**：点击后再 dispatch 同一任务，被点 Agent 的 pCTR 上升（任务#2 实测 0.5→0.5666；任务#3 复用已训权重起评 0.5728——**模型跨任务生效**）。
**练习**：打开 `v1.js` 把 idf 公式的 +1 去掉，重跑测试看哪些用例还绿哪些红了，体会平滑项的作用。
**理解题**：三层各自解决上一层的什么遗留问题？为什么无数据维度给中性 50 而不是 0？（冷启动不惩罚新人）

## 第 9 站 · 队列与 Go 引擎：手写 RESP + 重试死信

**学什么**：Redis list 当队列（LPUSH 头进 + BRPOP 尾出 = FIFO）；RESP 协议长什么样；指数退避；死信队列。
**读什么**：`server/queue.js`（生产者，JS 版 RESP 编解码+流式解析）、`engine-go/main.go`（消费者，Go 版）、`engine-go/index.md`（设计决策表）。
**跑什么**：

```bash
redis-cli llen queue:match          # 当前积压
redis-cli llen queue:match:dead     # 死信（里面有之前实测的伪任务 999）
tail -20 /tmp/aladdin-engine.log    # Go 引擎 BRPOP 循环日志
```

**复现死信路径**（很快，推荐亲手做）：`redis-cli lpush queue:match 99999` → 等 ~7 秒（1s+2s+4s 三次重试）→ `redis-cli llen queue:match:dead` 变多 → `curl localhost:3001/api/engine/overview` 里 match_runs 多一条 status=dead。
**读 RESP 原文**（协议恐惧症疗法）：`redis-cli lpush queue:match hello` 然后 `redis-cli lrange queue:match 0 -1`；再对着 `queue.js` 的 encode() 看 `*2\r\n$5\r\nLPUSH...` 每个字节。
**理解题**：为什么队列里只放 taskId 不放任务数据？RESP 解析为什么必须"先窥视够不够再消费"？BRPOP 超时返回 *-1 是什么意思？

## 第 10 站 · 五维评分 + admin 签名者 + 空投闭环

**学什么**：业务评分怎么设计才"讲得清"；后端持私钥替链写数据（relayer/admin 模式）；空投两段式（记账→批量上链→销账）。
**读什么**：`server/scoring.js`（质量70/速度15/价格10/响应5，无数据给中性 50）、`server/admin.js`（读 .env 私钥→ethers.Wallet→updateScore 上链）、`server/routes/airdrop.js`、`scripts/airdrop.js`。
**跑什么**：

```bash
curl -s localhost:3001/api/agents/1     # Agent#1 五维分全 100（走完了完单+仲裁）
curl -s localhost:3001/api/airdrop/pending   # 空投待发账本（现已清零）
```

**看什么**：Etherscan 上 Agent#1 的 score=100——注意这是**后端私钥签名写上去的**，不是前端。
**练习**：读 `scripts/airdrop.js`（聚合→上链→mark-sent 三步），想想为什么要 UNIQUE 约束防重复记账。
**理解题**：为什么记账（Relayer）和发放（owner 批量）分开？答：链上批量操作贵且慢，日常只记账，攒一批再发——这就是"空间换 gas"。

## 第 11 站 · 前端七屏 + 全链路实测

**学什么**：wagmi v2 钩子（useAccount/useReadContract/useWriteContract）、写后等确认（waitForTransactionReceipt）、读走公共 RPC 写走 MetaMask 的分流。

**理解题**：前端为什么"读直连 RPC、写走 MetaMask"？草稿先落库再质押的完整时序是什么？
