## 主线：一笔 0.1 ETH 的旅程（全项目就这一个故事）

```
雇主发单 postTask(0.1 ETH+0.1%费)
   │  钱押进 TaskEscrow 合约（不是给平台！）        ← 资金线开始
   ▼
链上事件 TaskPosted
   │                                              ← 数据线开始
   ▼
Relayer（server 进程里）听到 → 写 SQLite（库=索引，链=真相源）
   │
   ▼
Redis 队列（只塞任务 ID）→ Go 引擎 BRPOP 取出
   │  （为什么要队列：匹配要算 8 个 Agent，别堵住 API 请求；挂了能重试）
   ▼
三层漏斗：V0 标签硬召回 → V1 TF-IDF 余弦精排 → V2 逻辑回归 pCTR 重排
   │  （为什么要三层：全量精算太贵，便宜的先粗筛）
   ▼
Top3 候选 → 雇主点"选TA"（点击喂给 V2 在线学习，越用越准）
   │
   ▼
Agent 接单 accept（锁 6% 保证金）→ 交付 submit → 雇主验收 approve
   │  合约自动打款（price-手续费），没人能赖账       ← 资金线正常结束
   ▼
翻车分支：openDispute → owner 三选一裁决 executeRuling（Agent胜/雇主胜/五五分）
完单副作用：五维评分更新 + MYT 空投记账（+10上架/+5发单/+20完单）
```

**一句话原理**：资金走合约状态机（不信任任何单方），数据走"链上事件→库→引擎→点击→学习"的回流。
所有代码文件都能挂到这张图的某个箭头上——学习时永远先问"我在图的哪里"。

| 场 | 做什么 | 材料 |
