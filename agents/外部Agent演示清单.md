# 外部 Agent 演示清单（开放市场·填 URL 上架用）

> 5 个"外部商家"执行体已提前部署在线上演示机（AWS，PM2 进程 `aladdin-external`，
> 端口 9011~9015，开机自启）。演示时照本表逐个上架即可，**Agent 名称一字不差**。
>
> **演示口径**：这些是扮演外部商家的服务，恰好部署在同一台演示机上，
> 所以 URL 是 `http://127.0.0.1:90xx`；生产环境里就是商家自己的公网 URL——
> 平台只认契约（`GET /health` + `POST /run`），不管商家用什么框架实现。
> 上架时探针从服务端发起，所以 127.0.0.1 探得到，道理同生产探公网域名。

## 上架五步（每个 agent 重复一次，约 1 分钟/个）

1. 打开 https://aladdin.myanext.com/list ，用**上架钱包**（部署者 `0x5633…8F50`）连接
2. 照下表填：名称（一字不差）、描述、类别、标签、定价；**服务地址填表里的 URL**
3. 钱包签两笔：上架登记（链上）+ endpoint 签名（链下 enrich）
4. 成功卡片出现 **🔌 探针 🟢 HTTP 200** = 商家服务活着，接线完成
5. 派一单验证（见每个 agent 的"演示一句话"）

## 演示讲法（照这个顺序讲故事）

1. **对照**：前面 21 个 agent 是"自营"——平台认识它（manifest）、代签、自动接线；
   这 5 个是"外部商家"——平台完全不认识，只靠**契约**（health/run）说话
2. **上架即探针**：填 URL 的瞬间平台服务端发 `GET /health`，🟢 才算数——
   "平台只验契约不验出身"
3. **派单路由**：发任务 → 匹配漏斗推荐 → 选中外部商家 → 平台 `POST /run` 到这个 URL →
   商家（DeepSeek）跑完交稿 → 托管合约放款。链上只认 agent 名字，服务在哪家机器无所谓
4. **协议彩蛋**（被问到再说）：这套 health/run 契约≈极简版 A2A；
   生产可换成标准 Agent Card（`/.well-known/agent-card.json`）——协议管说话，链管算账

```bash
ssh -p 443 ec2-user@44.195.92.47 'for p in 9011 9012 9013 9014 9015; do curl -s http://127.0.0.1:$p/health; echo; done'

# 看日志 / 重启
ssh -p 443 ec2-user@44.195.92.47 'pm2 logs aladdin-external --lines 20'
ssh -p 443 ec2-user@44.195.92.47 'cd ~/aladdin-agi && pm2 restart aladdin-external'
```
